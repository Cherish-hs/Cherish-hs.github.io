## 四、关于容器内部进程的控制

- ****为什么杀掉 launch 进程后，其子进程 gz 还会一直运转？这与 sleep infinity 有什么关系？在宿主机终端杀掉父进程，其子进程会跟着消失吗？****

  > 杀掉父进程不代表子进程一定会退出。子进程可能被重新托管给其他进程，是否退出还取决于程序自身的处理方式、信号传播和进程管理机制。容器里的 `sleep infinity` 通常只是作为容器的主进程（PID 1）让容器持续运行，它不会自动负责关闭其他进程。因此，结束 ROS 2 的 `launch` 进程后，`gz` 等子进程仍可能继续运行；在宿主机终端杀掉父进程也一样，子进程不一定会跟着消失。可以用 `ps -ef --forest` 或 `pstree -ap` 检查进程关系，并在确认目标后单独停止残留进程。

## 五、容器中使用图形界面相关问题

**为什么 `xhost +si:localuser:root` 在电脑重启后要重新执行？**

- xhost : 管理x11 显示服务的访问控制。

- `+si:localuser:root`：允许被 X11 识别为本地 `root` 用户的客户端连接。

- `+`：添加允许规则。

> ***为什么重新登录后可能失效？***
>
> 因为 X11 的访问控制规则通常属于当前 X Server 会话。注销、重启或桌面会话重新创建时，原来的规则可能消失。

关于容器的权限

- UID 与 GID

> UID (User ID):用户ID,用数字标识一个用户
>
> GID(Group ID):用户组ID...
>
> Linux 通常用 UID `0` 表示超级用户 root；普通用户通常从 UID `1000` 开始

## 六、常用操作

```
# 查看正在运行的容器
docker ps

# 查看所有容器，包括已停止的
docker ps -a

# 查看容器详细配置
docker inspect tb3-gpu

# 启动、停止、重启
docker start(stop、restart) tb3-gpu

# 进入 ----------------

# 以容器默认用户进入
docker exec -it tb3-gpu bash

# 以 root 用户进入
docker exec -u root -it tb3-gpu bash

# 尝试以 UID 1000、GID 1000 进入
docker exec -u 1000:1000 -it tb3-gpu bash

# 退出 --------
exit
```

#### 镜像常用命令

```
# 查看本地镜像
docker images

# 下载镜像
docker pull ubuntu:24.04

# 查看镜像详细信息
docker image inspect ros2-humble-tb3:latest

# 删除镜像
docker rmi 镜像名
```

删除镜像前要注意：如果有容器正在使用它，Docker 可能拒绝删除。不要为了清理空间而随意删除仍在使用的镜像。

#### 创建容器与运行容器

```
# 根据镜像创建并启动一个新容器
docker run -it --name test-ubuntu ubuntu:24.04 bash

# 在后台启动一个容器
docker run -d --name my-nginx nginx

# 查看容器的退出状态
docker ps -a
```

`docker run` 通常会创建一个新容器；`docker start` 则是启动已经创建过的容器。两者不要混淆。

---

#### 删除容器与清理资源

在宿主机执行

```
# 删除已停止的容器
docker rm 容器名

# 强制删除容器（可能会先停止运行中的容器）
docker rm -f 容器名

# 删除未使用的悬空镜像
docker image prune

# 查看 Docker 磁盘占用
docker system df
```
